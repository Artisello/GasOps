# Step 9 — Automated Intelligence

## Two deployment modes

- **GitHub Actions diagnostics**: daily at 07:23 UTC (08:23/09:23 Italy), best effort, manual dispatch supported, no PR triggers, read-only permissions. After reviewing provider terms, set repository Actions variable GASOPS_MONITOR_ENABLED=1 and GASOPS_MONITOR_SOURCES to a space-separated subset of entsog acer mase. Default off. The workflow logs only status and uploads a diagnostic JSON (30 days); no numeric observations, original files, credentials or session data are uploaded. GitHub-hosted runner is ephemeral; no persistent revision archive in this mode. GitHub schedule can be delayed or disabled after 60 days without repo activity. No guarantee of availability or zero cost under every billing policy.
- **Private persistent monitor**: run the same CLI on a trusted local machine/cron with a persistent private GASOPS_STATE_DIR. Explicit terms confirmation required. Example:

```bash
python -m gasops_app.monitoring --confirm-terms --sources entsog acer mase
```

Optional gie (GASOPS_GIE_API_KEY / legacy alias), terna (GASOPS_TERNA_CLIENT_ID / SECRET and GASOPS_TERNA_INTERVAL_START=1 after confirming experimental timestamp convention). Keep credentials in environment or private secret store, not repository. No job reads user-uploaded CSVs or private Snam data. Schedule on that machine e.g. daily 07:23 UTC; prevent concurrent runs, back up monitor.sqlite3 and keep directory private. No automatic retention deletion, review storage growth. The SQLite file is separate from the app state and Step 1 historical warehouse. Do not publish it, share through public runner artifacts, or use an untrusted self-hosted public-repo runner. Public workflow deliberately excludes authenticated providers. The app reads a local JSON report or imports a session-local diagnostic from Actions; it does not fetch GitHub artifacts automatically.

## Scope and limits
ENTSOG: one seven-day query for existing three SRG exit aggregates, full day required for derived combined proxy. ACER: one historical CSV; native contract still to verify live. MASE: official native CSV download, structural-only pending; never produces production KPIs. GIE: 14-day IT stock and filling, Terna: 14-day power data via existing authenticated parser, normalized records only, not native raw. Jarvis, GME, Open-Meteo not scheduled; access/usage rights or model needs require separate validation. API requests bounded, no retries and no unrestricted or unauthenticated scraping; use per-source permissions.

Private DB deduplicates original payloads by source and SHA-256, retains each successful retrieval event (even identical bytes) with UTC time and observations. Terna records deliberately normalized and labelled experimental; no token stored. As-of API returns last acquired nonmissing value for each natural key, including acquisition timestamp/digest; does not assert that the provider published it at that time. Missing latest slots do not replace prior values; report current coverage separately. Revision counts compare overlapping values against prior acquisitions; no sums across units. Outlier count compares new dates only with prior 28 days (>=14 values), using median and MAD, floor 10% of median. These are study signals, not operational limits, no automated decisions. Diagnostics-only counts for revisions/outliers are null, not zero. No private report values in hosted job logs. Failure isolation allows other providers to complete, then exits nonzero if any failed; skips and raw_pending are distinct.
UI: KPI operativi > Monitoraggio fonti. Import diagnostic JSON or read local report. No automatic source calls. No automatic integration of accumulated history with forecast yet; `Archive.as_of` is the basis for future vintage-aware studies. Tests are deterministic, no official live operational certification.
