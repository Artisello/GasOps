# Terna historical archive and Snam model

Terna official Actual Generation and Total Load documentation describes historical values to D-1, refreshed at midnight. Existing API client limits each request to 14 gas days through D-2 and assumes interval-start timestamps, Rome 06–06; convention still needs confirmation. History stores complete observed national generation/load only, no load forecasts, with acquisition completion timestamp, per-day metric and slot count including DST. Each acquisition gets a content hash; revisions retain their own timestamp. No credentials/raw API payloads committed. UI collects successive windows using current Secrets, session-only; export/import normalized JSON for durability. Imported timestamps are declared, not independently authenticated. Existing app API flow preserved. No new scheduled public job.

Private persistent collection (environment credentials, operator verifies terms and quota before running):
python -m gasops_app.terna_history --confirm-terms --first 2025-11-01 --last 2026-11-16 --max-windows 28
Each window <=14 days, 60 seconds between windows, explicitly capped, stops on error or absent load, successful ranges preserved in private SQLite under GASOPS_STATE_DIR. Resume from failed window. Default collects latest 14 days. Export with:
python -m gasops_app.terna_history --export igor-terna-history.json
Import JSON in Terna daily view. Keep local database and JSON private; never upload as public GitHub artifact. No on-demand API calls from forecast. No hard guarantee on retention, terms, quotas or historical availability.
